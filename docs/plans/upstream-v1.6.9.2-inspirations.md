# F-03 灵感大厅、画廊与内容目录讨论

固定基线为本地 `15861487c12780d08043ed7d7eca864deea73c53` 和官方 `19eec9bc4e71cbb5941b9dc4139fd6487fc91015`。F-03a/b/c/d 均已确认，候选实现及专项验证如下；完整构建、真实路由、迁移与数据库事务尚未验收，未启用新模块。

## 冲突与调用链

本地首页使用后端维护的精选灵感与个人提示词，保留 `/inspirations`、`/user-prompts` 业务 API、运营排序、启用状态、封面资源及当前个人库页面。官方在首页嵌入灵感大厅和动态画廊，新增按来源、分类和类型筛选、搜索、收藏、隐藏、改写、自建、JSON 导入/导出；其个人状态另存在按用户隔离的浏览器 localforage，不会自动同步本地既有后端个人库。

- 首页交叉点：`web/src/pages/create/index.tsx`、`creation-workspace.tsx` 与 `creation-inspiration-tunnel.tsx`。本地精选展示与官方大厅在同一位置发生文本/行为冲突，不能直接用官方首页覆盖。
- 官方目录：`web/src/pages/inspirations/index.tsx` → `web/src/services/inspiration-catalog.ts` → 本站 `web/public/inspirations/*.json`；本轮固定快照，不是运行时自动向来源网站更新提示词。
- 画廊：`creation-inspiration-tunnel.tsx` → `loadGalleryPool()` → `gallery-pool.json`；另叠加代码内 22 项模板。
- 官方个性化：`web/src/stores/use-inspiration-store.ts` / `web/src/lib/inspirations/resolve.ts`；本地持久化：`web/src/services/api/inspirations.ts`、`user-prompts.ts` 及相应后端业务。收藏/改写状态与现有个人提示词怎样统一，须单独确认，不能把浏览器落盘称为服务端保存。

## F-03a：功能与内容采用范围

| 方案 | 行为 | 数据与权限影响 |
| --- | --- | --- |
| A，推荐 | 纳入可选的大厅、画廊和全部固定目录，新增模块首次默认关闭；现有首页精选、个人提示词和经营后台继续保留 | 管理员通过既有功能配置权限明确开放；不自动覆盖、导入或删除已有业务内容。个性化存储及外部封面策略另议 |
| B | 采用大厅/画廊的展示与筛选能力，只使用本地既有精选和个人提示词，本轮排除官方新增内容目录 | 继续由本地后端内容及权限管理；不增加三方目录和另一套个人内容存储 |
| C | 本轮排除新增大厅、画廊和内容目录，保留现有精选与个人库 | 不增加这些模块的页面、数据或初始化；适用的通用性能修复仍逐项核对 |

最终决定：**用户确认 A，纳入大厅、画廊和全部目录，新增模块默认关闭。** 保留本地首页精选、个人提示词及经营后台。先整合开关与可选展示，个人状态和封面加载按下列议题决定后再实现；不直接覆盖本地首页布局。

验收方法：默认关闭时不渲染或加载新目录；开启后搜索、分类、图片/视频筛选和按需加载可用；原精选排序、停用、封面资源、个人提示词与经营后台不变；账号隔离与保存状态准确；选用只预填可见草稿，确认模型后手动发送，不自动调用付费模型。

## F-03b：收藏、隐藏、自建与改写的保存位置

冲突链为 `InspirationHall` → `use-inspiration-store.ts` 的浏览器 localforage，与本地 `user-prompts.ts` → 后端个人提示词库。官方收藏、隐藏和改写默认仅保存在当前浏览器的账号作用域；本地个人库在服务端，支持其他设备访问。继续原样接入会形成两套个人内容。

| 方案 | 行为 | 数据与权限影响 |
| --- | --- | --- |
| A，推荐 | 统一到现有服务端个人库；收藏/隐藏等目录状态增加必要的账号记录，自建/改写复用个人提示词正文 | 保留旧个人提示词 ID、正文和封面，不把全目录自动导入个人库；需要配套状态表/字段及追加迁移。全部写入校验当前账号，不能因浏览器缓存成功显示服务端已保存 |
| B | 沿用官方浏览器个人状态，与现有服务端个人库并存，并明确显示保存范围 | 不迁移既有服务端数据；收藏、隐藏与改写仅当前浏览器/账号可见，不自动跨设备同步 |
| C | 本轮只接目录浏览和预填，不接收藏、隐藏、自建、改写及导入/导出写入 | 保留已有个人库的原有功能，不新增目录个人状态或迁移 |

最终决定：**用户确认 A，统一服务端保存，复用现有个人库。** 保留已有 ID、正文、封面及 500 条个人提示词上限；收藏和隐藏状态不复制整份目录正文。历史浏览器状态不在启动时静默搬迁，必要时通过用户明确导入处理；新增迁移编号仍待总表确认。验收覆盖既有提示词不变、账号隔离、重复收藏幂等、写失败不假成功、跨设备读取及封面引用保护。

## F-03c：外部封面加载

冲突链为 `inspiration-catalog.ts` 的目录 `image` → `InspirationCover` / 画廊图片。三份主目录中 355 项引用本地封面、964 项引用外部地址；画廊池 329 项都是主目录的子集且使用本地缩略图。官方图片进入可视区域即可加载其地址，采用目录不应默认为已经决定外部封面的加载方式。

| 方案 | 行为 | 数据与权限影响 |
| --- | --- | --- |
| A，推荐 | 本地封面正常显示，外部封面显示占位，用户点击后在浏览器加载 | 保留全部提示词，不自动抓取或写入素材库；选用内容仍需手动提交生成 |
| B | 模块明确开启后沿用官方懒加载，图片进入可视区域时加载外部封面 | 提示词与封面地址保留，浏览器会向对应外部图片主机发起请求；不自动保存到本地素材 |
| C | 本轮只显示本地封面，外部封面始终保留占位 | 全部提示词保留，不新增外部加载按钮或服务器代理 |

当前决定：**用户后续要求改为 B，外部封面接近可视区域时自动懒加载，无需逐张点击。** 早期选择 A 已由本次要求替代。大厅与详情共用 `InspirationCover`，使用浏览器原生 `loading="lazy"`，提前请求阈值由浏览器决定。验收覆盖默认关闭模块不加载目录/封面、本地封面展示、外部加载触发时机、失败占位、账号/页面切换与明暗主题。

## F-03d：隐藏目录与已保存改写副本

冲突链为 `InspirationHall.handleDelete` → `use-inspiration-store.removeEntry`。官方隐藏内置条目时同时清除该条目的改写和收藏；统一服务端个人库后，照搬会使保存的个人副本丢失或解除关联。

| 方案 | 行为 | 数据与权限影响 |
| --- | --- | --- |
| A，推荐 | 隐藏只控制大厅显示，保留已保存改写、收藏和个人提示词；恢复显示后沿用原副本 | 不隐式删除服务端个人内容；真正删除仍从个人库明确执行 |
| B | 隐藏时清除收藏并解除大厅改写关联，但保留个人库中的正文和封面副本 | 恢复大厅条目时显示官方原文；个人库副本仍可自行管理 |

最终决定：**用户确认 A，隐藏只改变展示，保留副本与收藏。** 验收覆盖隐藏/恢复前后个人提示词、正文、封面、收藏和关联一致；隐藏写入失败不得假成功。

## 候选实现与数据合同

- 新增 `inspirationHallEnabled` / `inspirationGalleryEnabled`，前后端默认 false，沿用 `admin.settings.features` 和本地二次确认。新模块放在现有精选之后，保留本地首页与个人库入口；按开关动态加载，关闭时不挂载模块或请求目录。首页文件还有其他跨模块冲突，本批局部接线不计为完整首页验收。
- `user_inspiration_libraries` 以用户 ID 为主键，保存 revision 和状态 JSON：收藏/隐藏 ID、目录到 `user_prompts` 的关联、显式导入身份映射，以及中文备用正文、分类、画幅和来源信息。主要个人正文、封面和原 ID 继续使用 `user_prompts`；不将整份目录导入数据库。完整账号注销清理新增状态。表已登记模型总表，追加迁移编号/顺序/校验和待统一确认，未执行迁移。
- `GET /inspiration-library` 仅读本人快照，首次读取不创建记录；`POST /inspiration-library/commands` 支持 save/favorite/hide/restore/delete/import。写入必须携带 `expectedUserId` 和 `expectedRevision`，前者只复核会话身份；版本不符返回 409 `inspiration_library_changed`，不得自动覆盖。已有个人库的创建、修改、删除也在同一账号状态锁下提交并推进版本。
- 编辑器绑定打开时的版本；确认删除和导入分别绑定确认开始/文件读取开始的版本，后台刷新不能替旧草稿换新版本号。收藏使用明确目标状态，重复请求不重复收藏；隐藏/恢复幂等。固定 1,341 个目录身份与后端嵌入清单一致，个人身份必须属于当前账号，不接受任意伪造目录键。
- 新建与改写保留原 500 条个人提示词上限及字段限制。显式 v1 JSON 导入复用个人记录，保留来源/署名/双语信息，事务失败不部分提交；缺失必需字段或不属于当前版本的目录 ID 明确拒绝。浏览器旧状态不自动迁移；只在用户明确导入后写入。
- 前端不再用 localforage 充当第二套个人正文库，仅保留按账号隔离的内存投影。收到成功回执才更新；失败保留编辑内容，账号切换/功能关闭清空投影，旧回执不发布。原文经现有个人库修改时保留旧中文版本并标记待核对，不静默删除，也不优先选用旧译文；用户在编辑器明确确认后解除标记。
- 内置路径封面、本人资源与 HTTPS 外部封面统一使用浏览器原生懒加载，无需点击确认；保留 `referrerPolicy="no-referrer"` 和异步解码。上传引用仍走原归属/就绪校验；内置静态图片仅放行指定目录且拒绝穿越路径。服务器不代抓外部图片，失败保留占位。画廊池仅使用已清点的本地缩略图，轮播继续尊重 reduced motion。

## 验证范围

前端本批联合回归共 60 项、3,154 个外层断言、17 个文件通过；五个包装另运行 61 个内层场景（个人库状态 13、封面/编辑器/可选模块 10、功能配置 9、既有工作台 19、工具后台 10）。使用 Happy DOM/API 替身，未启动浏览器或付费模型。目录身份/内容合同、默认关闭门禁、账号隔离、回执、旧版本草稿、封面点击及编辑失败保留均有专项依据；完整大厅、首页布局和真实页面未验收。

定向 ESLint、16 个无冲突 Go 文件的解析/gofmt 检查通过，Go model/kernel 两包通过。新增两个 API 路径和三个输入 schema 的独立 YAML 解析通过；整体 OpenAPI 仍有跨模块冲突，不计完整规范通过。新 prompts 四组事务/数据保护用例和 app 两组开关/空账号用例已补，但依赖尚未解决的 repository/schema 冲突，未运行。语法检查和 model/kernel 测试不能替代 SQLite/PostgreSQL、迁移或权限集成通过。
