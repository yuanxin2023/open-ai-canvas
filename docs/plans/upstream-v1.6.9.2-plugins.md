- 方案 C：接入完整官方推荐目录，保留其推广展示；仍需保留本地权限和用户明确确认安装的边界。
- 数据与权限影响：查询、验 Key、安装继续受现有渠道管理权限约束；不自动修改已有渠道。选择 A 时还需核对目录来源字段迁移是否被其他能力依赖，不能直接凭功能名删迁移。

## PLG-02：图片参数合同及旧配置语义

- 文件及调用链：插件 manifest 的 `imageParameters` → `protocol.ResolveImageParameters/ApplyImageParameters` → `app/image_parameters.go`、`model_capability*.go`、模型路由/报价 → 前端能力编辑器、生成合同与真实任务请求。OpenAI/Grok 等插件清单和打包归档也必须同步。
- 本地行为：图片尺寸、分辨率和质量通过既有能力结构管理；Grok 以 quality 保存 1k/2k；OpenAI 插件还将旧 quality 1k/2k/4k 分别映射为 low/medium/high。已有 SubRouter Gemini 协议及 ID 属于本地保护项。
- 官方行为：以插件声明的参数表作为约束来源，分辨率与质量独立；渠道只能收紧插件边界，不能伪造类型、上游绑定及计价资格。新参数保留 false/0，未声明字段拒绝；老结构作为执行投影。官方新增了一部分旧 quality 档位导入，但不能把所有协议的同名值当成同一语义。
- 方案 A（推荐）：采用新合同，逐协议保留旧语义。Grok 的 1k/2k 等价迁至分辨率；OpenAI 旧档位继续按 low/medium/high 质量执行，不能直接当成新增 resolution 改变请求。旧渠道 ID、上游模型键、价格金额、历史订单不改写；价格条件如需字段转换，必须与请求和报价等价核对。SubRouter Gemini 保留原身份及可执行映射。
- 方案 B：本轮继续旧参数合同，延后依赖新合同的参数编辑及相关能力；需要系统撤回已自动合入的新调用链，不能只保留旧 UI。
- 数据与权限影响：只做可证明等价的配置转换；未知值、互相冲突或无法确定价格条件的配置先明确拒绝执行并给出待核对原因，不静默选择默认值、放宽范围或重设价格。管理员修改仍受现有渠道/模型权限约束。
- 验收：旧 Grok/OpenAI/Gemini/SubRouter 配置的报价与上游 payload 等价，分辨率/尺寸/质量的 SKU 选择和最终 0.01 积分结算一致；未知值拒绝、禁用参数不发送、false/0 保留、插件上下界不可扩宽、旧订单不重算。
- 最终决定：**采用新合同，逐协议保留旧语义。**用户已确认；候选正在同步配置读取、报价/价格条件、任务准入、执行和前端校验。未声明新合同的既有插件保留原能力配置路径，不能对它们提前改写质量字段。验证结果及剩余依赖在本批结束时记录。

## PLG-03：OpenAI 参考图公网地址与内联

- 文件及调用链：`openai-images/manifest.json:requiresPublicMediaUrls` → `providerMediaHydrationPolicyFor` → `hydrateProviderMedia` → 插件请求；相邻 `builtin_test.go`、`provider_test.go` 及资源读取/协议测试。
- 本地行为：OpenAI Images 2.0.0 声明必须公网 URL，除遮罩等已有特殊路径外需提供可用地址。
- 官方行为：2.1.0 改为允许内联图片，测试明确要求无需公网存储也能提交；直接采用会让现有地址偏好发生变化。
- 方案 A（推荐）：支持两者；可用对象存储签名 URL 优先，本地资源允许受限内联。继续使用资源归属、就绪状态、图片类型及大小校验；不因内联绕过后端读取和出站安全限制，不把图片或密钥写入日志。
- 方案 B：继续强制公网 URL，保留本地合同；官方本地资源内联能力不纳入本轮，并同步清单、归档与测试。
- 数据与权限影响：不新增公网资源和权限，不改写已有资源记录；内联会增加后端读取和请求体占用，必须遵守现有上限。签名地址不可用的失败不能无条件吞掉，只有可安全读取的自有资源才允许回退。
- 验收：对象存储 URL、无对象存储的本地图片、遮罩/顺序、缺失或跨用户资源、类型/大小上限及签名异常；模拟上游检查实际 payload，不调用付费生成。
- 最终决定：**URL 优先，允许本地资源内联。**用户已确认；候选正在同步清单、媒体准备、测试与归档。对象存储地址失败只在可读取本用户资源并通过上限检查后回退，不直接相信任务中附带的图片内容。

## PLG-02 / PLG-03 实施与当前验证

- Go 与前端分别使用同一张逐协议规则表：OpenAI 的旧 1k/2k/4k → low/medium/high；Grok 的 low/standard/1k → 1k、medium/hd/high/4k/2k → 2k；Gemini 与本地 SubRouter 的 low/medium/high → 1k/2k/4k。别名来自本地起点的实际请求模板，不按显示名称或模糊供应商名推断。
- 旧 auto 保留原模板省略 `imageSize` / 分辨率的行为。配置、任务准入/执行、价格条件及目录公开投影同步处理；读取不改写持久化配置和历史订单，管理员明确保存才采用转换结果。未声明新参数合同的旧插件不提前改写其能力配置。
- 有歧义、未知值、无效默认值或超出插件边界的旧声明明确拒绝，前端保留原值并提示核对；管理员可明确选择重新配置。有效但不匹配某次请求的价格档仍可按既定选择规则路由；存在无效活动价格配置的渠道不会通过忽略该档而落到另一通配价格。
