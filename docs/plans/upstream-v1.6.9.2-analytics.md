# ANA-01：经营概览新增指标

最终决定：用户已确认接入全局可用余额与范围消耗，沿用本地已结算订单去重口径。候选实现完成，app 整包与页面验收待剩余公共冲突解决。

- 文件与调用链：analytics.go 的 AdminAnalytics → repository.AnalyticsAPICallLogs / BillingOrdersByIDs → analytics_finance.go → auth.ts 的 AnalyticsOverview → analytics-panel.tsx，继续使用现有 http 调用。
- 本地行为：只统计已结算账单，按账单 ID 去重，核对用户、实际结算渠道和 billable；重试、轮询、下载、辅助请求及退款不重复增加收入。供应商成本缺失时不伪造利润。
- 官方行为：增加全局余额、范围消耗和每日消耗字段，原新增分支直接累计日志 BillingAmount，无法保证与本地结算口径一致。
- 可选方案：接入指标并复用本地结算记录；或本轮不新增指标。用户已选择前者。
- 推荐与实现：总余额只汇总当前全部用户可用积分，不含冻结，明确不随筛选变化。范围和每日消耗共用现有 analyticsFinancialRecords 结果，与原经营财务汇总一致，不从单条日志的展示金额计算，不反查当前商品/模型价格。
- 数据与权限：不重算、改写历史账单或余额；继续使用数据概览权限，日志/资金管理的其他权限不扩张。
- 验收：同单重试、轮询、下载、退款、仅预授权、免费单、已结算单、错误归属和旧渠道、模型筛选、全局余额不随筛选变化、趋势与总计一致、无权限拒绝。已有经营测试已补充相应金额与全局范围断言，尚未运行 app 整包；页面构建和浏览器验收未完成。
