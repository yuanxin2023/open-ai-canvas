# 用户资源配额

管理员在“用户与服务 → 用户管理 → 管理 → 资源配额”逐项配置普通用户。每项可选择继承全局或单独设置，显示全局默认、已生效值和适用的已用量。单文件限制和保留天数没有累计用量。分栏独立保存，切换保留草稿，关闭提示未保存内容；保存失败保留输入。

全权限管理员还可在“管理员配置 → 管理 → 资源配额”配置全权限或模块管理员账号，包括自身；模块管理员不能自行读取或修改管理员配额。该分栏位于“安全与状态”之后，提交和二次确认期间锁定弹窗其他操作；账号资料、权限、密码和调账草稿独立保留。

## 继承与范围

全局默认仍由“资源与请求策略”配置。未覆盖的项目动态继承全局，已有账号无需回填默认数值；显式覆盖即使与当前默认相同，也保持独立。改回继承后，之后的全局调整立即生效。

| 字段 | 单位 | 允许整数范围 |
| --- | --- | --- |
| `resourceUploadMB`、`generatedFileMB` | MB | 1–999 |
| `dailyUploadMB`、`structuredDataMB` | MB | 1–999999 |
| `storedFileGB`、`taskDataGB` | GB | 1–999 |
| `assetCount`、`canvasCount`、`taskCount`、`apiCallLogCount` | 条/个 | 1–999999999 |
| `recycleBinRetentionDays` | 天 | 0–365 |

MB、GB 沿用后端的 1024 进制。普通上传、远程导入和分片完整文件必须小于单文件上限；生成文件可等于上限。文件日总量和已存储总量必须小于上限；结构化与任务数据可等于上限。每日文件总量按 UTC 自然日计算。

## 生效与用量

统一入口 `Service.UserRuntimePolicy(userID)` 将当前全局资源策略与稀疏覆盖合并。上传、远程导入、生成文件保存、画布/素材写入、任务创建与完成、文本增量、请求日志和回收站清理均使用目标用户的生效额度。分片开始校验声明的完整大小，合并保存时再次校验实际完整文件及当前额度；不能通过分片绕过限制。

文件容量计入已持久化且状态为 `ready` 的用户上传、生成图片/视频/音频及会话附件。按 Provider、Endpoint、Bucket、ObjectKey 去重，同一物理对象重复引用不重复计费；回收站文件仍占空间时继续计入。仅保存外部 URL 的记录只计入已有数据统计，不估算远端文件大小。上传/生成沿用文件容量与每日用量预留，失败释放预留，幂等重试复用已有对象。

结构化用量沿用素材/画布的 JSON 容量；创作写入保留已有创作会话容量校验。任务数据用量包含任务正文、结果、文本增量和日志。数量按各类记录分别限制，不把这些容量混入文件存储。管理员可以把额度下调到已用量以下；既有内容保留，读取、删除和不增加容量的更新仍可执行，新增或增长受限制。

回收站按每个用户的生效保留天数分批扫描；`0` 表示不自动清理。自动删除仍复用归属、引用检查与资源删除 Outbox，其他记录仍引用的资源不会删除。

## 数据与接口

schema 51 新增 `user_resource_quotas`，`user_id` 唯一，`overrides_json` 只保存显式覆盖，另保存修改管理员和创建/修改时间。PATCH 合并与管理审计在同一事务中执行，全部恢复继承后删除覆盖记录；永久注销用户同步删除该配置。

`GET /api/admin/users/:id/resource-quota` 返回当前覆盖、默认、生效和用量。`PATCH` 仅接收 `overrides`，其中数值设定覆盖，`null` 恢复继承，未传项保持原状。需要用户管理权限，不能操作管理员目标；字段及范围由后端校验。成功返回最新完整投影。

管理员账号使用 `GET/PATCH /api/admin/administrators/:id/resource-quota`，合同相同，但需要全权限管理员且目标角色为管理员。服务端与保存事务均校验目标角色；管理员修改使用 `administrator.resource_quota.update` 审计。普通用户与管理员共用同一张配置表和生效入口，无需新增迁移；升降级保留配置，永久注销清理配置。

本阶段只支持管理员手动配置；套餐绑定、会员等级和到期降额尚未实现。
