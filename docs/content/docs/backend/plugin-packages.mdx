插件清单是构建合同。直接维护 `plugin-packages/<插件 ID>/manifest.json`、README 和接口文档；第一方只分发 `.canvas-plugin`，导入仍支持 `.yingce-plugin` 与 `.lovwow-plugin`。第三方原有身份和格式保留，不能通过全仓替换修改供应商 ID、协议标识或持久化键。

`generate-catalog.mjs` 只为缺失的目录创建初始文件，已有维护中的清单不会被旧模板覆盖。`embed-documentation.mjs` 从真实清单更新完整接口文档，替换旧生成标记，再嵌入清单；不把文档中的模板当作运行合同。

## 构建与校验

在包含 Go、Node 和 zip 的构建环境运行：

```sh
sh plugin-packages/build-packages.sh
```

构建先同步文档，再从当前源码生成支付执行文件并打包。默认覆盖 Linux、macOS、Windows 的 amd64/arm64；`PAYMENT_PLUGIN_GOOS` 与 `PAYMENT_PLUGIN_GOARCH` 可明确选择单个平台，`PAYMENT_PLUGIN_CGO_ENABLED` 默认为 0。宿主机默认执行文件采用 Linux amd64；平台文件的名称包含真实目标信息，不能只复制改名来冒充另一平台。

所有分发包的 SHA-256 写入 `plugin-packages/SHA256SUMS`。在对应目录核对：

```sh
cd plugin-packages
sha256sum -c SHA256SUMS
```

只更新支付包可使用 `--payments-only`。包内声明、README、接口文档和执行文件必须与目录一致；构建不会创建业务渠道、模型、价格或用户数据。

## 新增协议与既有配置

本轮新增的 11 项协议作为可选能力提供，首次注册默认关闭；已有插件的启停状态保留。管理员启用插件并配置渠道、模型和价格后，才会形成可用业务能力，不因此开启新增工作台入口。

图片参数以插件声明为边界，渠道只能收紧范围。分辨率、质量和像素尺寸分开处理；旧配置按具体协议进行可证明等价的投影，报价、价格条件、任务准入和执行同步使用。未知或冲突值不静默重置默认值，不把未配置的价格自动匹配到相邻规格，也不重算历史订单。

OpenAI 参考图优先使用可用对象存储签名地址；本地内联必须关联本人已上传资源，并校验归属、状态、图片类型及大小。签名失败不代表内联已获准，仍须能读取并通过相同检查。遮罩的既有内联路径保留，但实际内容同样受类型和大小限制。

AutoDL 当前分发只提供视频。旧音频与 IndexTTS2 配置数据保留，对应模型和任务不再获准执行，不自动迁到其他供应商；已有未完成任务的资金、退款与恢复行为须在升级前演练。

## 支付插件升级

新单使用启用的支付渠道；暂停只停止新单，旧单仍可查单、关单和验签。存在仍占库存或限购名额的未确认订单时，升级和卸载受到保护，同版本替换为不同内容也不能绕过检查。

启动引导更新已安装支付包前，同样检查未决订单：有未决订单保留旧包，没有未决订单才更新；无法核对时延期更新。相同内容的重装不触发替换。可先暂停新单，结清存量后手动升级。

模型协议专项、支付库测试和平台构建只能证明相应范围。数据库事务、实际启动、跨进程安装/下单并发、渠道回调与生产升级仍需单独验收。
