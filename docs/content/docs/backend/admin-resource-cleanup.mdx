# 管理员资源清理

管理员在存储资源后台成功删除图片、视频、音频或模型文件时，系统同时移除以该资源为主体的独立媒体素材及回收站卡片。角色卡等复合素材保留设定；删除封面、缩略图不删除仍有有效主体媒体的素材。

画布失去部分媒体时清除对应媒体；节点仍有其他版本则切换到剩余版本，否则删除节点、连线和相关引用。时间线和预演中的失效媒体同步移除。原本包含媒体的画布在全部媒体被删完后永久删除，包括剩余文本、提示词和分组；纯文本画布不受影响。外部媒体地址计入剩余媒体，聊天记录和历史快照不计入。

删除预览显示将删除的素材、节点和画布数量，结果返回实际影响。活动任务、Agent、用户头像等保护引用继续阻止删除；普通编辑租约可随清理撤销。文件仍通过 Outbox 异步回收，共享物理对象保持现有保护。任意结构化清理或审计写入失败时事务回滚。

## 用户页面同步

登录后先重放管理员清理变更，再合并本地数据。前台每 15 秒核对，恢复网络、窗口获得焦点及画布变更通知触发核对。当前画布被删时提示并回到画布列表；资产与画布列表自动刷新。

每个页面会话从游标 0 重放持久清理标记，确保多个标签页分别清理各自内存；后续使用会话内递增游标。本地持久化成功后才保存游标。旧素材、画布、待提交操作和撤销历史不能将删除内容重新上传。受影响画布的未提交修改保存为独立恢复材料，再采用服务端清理结果；恢复材料不进入正常列表和自动同步。

## 历史残留专项清理

先升级到 Schema 114，备份目标数据库，并在副本上预览、演练和核对数量。命令必须显式设置 `CANVAS_BACKEND_DATA_DIR`，或设置 `CANVAS_DATABASE_DRIVER=postgres` 与 `DATABASE_URL`。不得使用默认数据库路径。

```bash
cd backend
# 使用上述环境变量指定已备份的目标；默认仅预览，不做迁移或数据清理。
go run ./cmd/cleanup-admin-resources
# 在副本演练与数据核对完成后，显式应用。
go run ./cmd/cleanup-admin-resources --apply
```

命令只采用成功的 `resource.delete` 审计中 `deleteMode=admin_force` 及用户归属证据，并重新确认资源记录不存在；同一用户的资源合并判断，按用户事务处理。仍存在、受保护或正文损坏的记录列为跳过项；证据不足的文件缺失不作为删除依据。JSON 输出包含 apply、scanned、impact、skipped；有跳过项时退出码为 2，执行错误退出失败。重复执行不额外删除内容；不会在服务启动时运行，也不会因清理画布而删除所属业务项目或其他资源。

预览使用只读事务，不写业务记录、不迁移、不初始化插件；SQLite 读取时可能生成 WAL/SHM 协调文件。应用模式也要求数据库已存在，避免路径写错时创建空库。
